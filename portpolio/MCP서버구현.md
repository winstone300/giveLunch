# mcp 서버를 통한 음식 정보 적재 자동화

`Python` `MCP` `Spring Boot`

## Background

---

- 음식 영양 정보 조회 시 DB에 데이터가 없으면 외부 API를 호출해 정보를 조회하는 구조였습니다.
- DB에 저장된 음식 정보가 많을수록 외부 API 호출 빈도를 줄이고 평균 응답 속도를 안정적으로 유지할 수 있었습니다.
- 기존에는 관리자가 관리자 페이지에서 직접 음식을 검색하고 저장해야 했기 때문에, 데이터 적재가 수작업에 의존했고 반복 업무 부담이 컸습니다.
- 수동 저장 방식은 대량 적재가 어렵고, 운영자 개입 없이는 DB 확장이 느리다는 한계가 있었습니다.

## Approach

---

### 기존 관리자 저장 로직 재사용

- 새로운 저장 로직을 별도로 만들지 않고, 기존 관리자 페이지에서 사용하던 Spring 저장 로직을 재사용
- 이를 통해 자동화 도입 이후에도 저장 규칙과 데이터 정합성을 동일하게 유지

### Python MCP 서버 구축

- `stdio` 기반 Python MCP 서버를 구축해 음식 검색과 저장 기능을 도구 형태로 제공
- `search_external_foods`, `save_foods`, `import_foods_by_name` 3개의 툴을 노출

### Spring Agent API 연동

- MCP 서버는 직접 DB에 접근하지 않고 Spring 애플리케이션의 Agent API를 호출하는 중계 계층으로 설계
- 인증
    - API 고정 키 기반 인증 → 현재 로컬 개발 단계이기에 해당 인증 방식으로 충분하다 판단
    - “/agent/api/**” 요청 시 키 일치 여부 판단 후 권한 부여

## Results

---

| 항목 | Before | After | 효과 |
| --- | --- | --- | --- |
| 음식 정보 적재 방식 | 관리자 페이지에서 수동 검색 후 단건 저장 | MCP 서버를 통한 검색/저장 자동화 | 반복 업무 제거 |
| 대량 데이터 적재 | 불가 | 이름 목록 기반 일괄 import 가능 | 적재 효율 향상 |

## Problem

---

- 기존 로직이 단건 저장 뿐이라 에이전트가 음식 저장 시 음식 개수 만큼 툴 호출
- 정확한 성능 평가 기준이 없어 이후 개선 작업 시 성능 향상 여부 판단이 모호함
